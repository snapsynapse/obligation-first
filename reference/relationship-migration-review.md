# Relationship migration review

The shared fingerprint checker requires a reviewed migration when an existing relationship is removed or retargeted. New-edge-only additions remain under owner source admission. Nested removals and retargeting are detected but fail closed until a verified owner mapping adapter is available. Array order alone is not a migration.

The comparison uses the fingerprint in the owner's committed `HEAD`, or the full commit supplied by `SOURCE_ADMISSION_BASE` in source CI. It reads that comparison independently of the editable expected fingerprint, including during `--write`. A manually refreshed expected file cannot erase the review requirement. An unavailable comparison commit or committed fingerprint fails closed.

CI must supply an explicit full comparison commit; it cannot silently compare a committed change with its own HEAD baseline. Owner canonical workflows pass their PR base or push-before commit and fetch complete history. Their remote OF pins remain at earlier commits until coordinated delivery.

The owner retains `tests/fixtures/of-relationship-migrations.json` beside its expected fingerprint. Each entry contains the exact change (`kind`, `subject`, `predicate`, sorted `old_targets` and `new_targets`), a reason, and a declared reviewer/type with an actual non-future UTC review time. The review packet digest binds the change, reason and source-admission reference using canonical JSON SHA-256.

The reference must resolve to one native-record receipt in the owner's canonical `data/admission/receipts.json`. It binds the complete selected receipt digest and names the reviewed units supporting the migration. The source review must precede the migration review. The projected subject must map to the same native-record receipt through a supported owner identity mapping. The named direct relationship unit must bind the exact before/after target values through its admitted unit hashes and displayed candidate content. An unrelated title review cannot authorize an anchor retarget, even if the migration packet is recomputed. The checker also executes the owner's source-admission gate; receipt presence without current owner acceptance is insufficient. Source bytes, document identity, qualifications and changed native-unit validation remain the owner's responsibility.

New subjects and previously absent predicates remain under source admission; this gate does not invent a prior relationship for them. A v2 fingerprint cannot establish the historical absence of nested edges it did not capture. Existing v3 nested target-set changes are detected and blocked; their acceptance needs a verified mapping adapter. Current accepted mappings cover explicit direct native relationship fields and the AI Incident Law anchor alias. Derived relationships and additional owner identity mappings are not accepted merely on a reviewer declaration. Non-edge nested qualifications remain protected by exact fingerprint drift checks.

The review declares source consistency, not authenticated human approval, legal applicability, comprehensive source discovery or corpus accuracy. A disputed ontology mapping still requires its human decision. Retained migration entries describe their own transitions and do not authorize later transitions. A stale old/new set, packet, source receipt, missing review or failed source gate rejects the current migration.

Implementation: `scripts/lib/relationship-migrations.mjs`, called by `scripts/check-adopter-fingerprint.mjs` for ordinary checks and writes. `scripts/test-relationship-migrations.mjs` exercises exact transitions, source bindings and real temporary Git history, including an attempted baseline-refresh bypass. It runs in the existing hardening gate.
