# P1 semantic federation mitigation

Scope: Obligation First shared validation, review F06 and F07. Implemented locally on 2026-09-04; publication is separate.

`verify:federation` rebuilds each adopter's current working-tree sources in an isolated temporary directory and compares the complete OF export. It includes tracked and new unignored files, respects source deletions, and uses installed dependencies through NODE_PATH. It excludes the OF projection from the copied inputs so obsolete artifacts cannot survive a rebuild unnoticed, and rejects a build producing no projection artifacts. It does not install packages or modify the original checkout. A missing dependency or failed build fails closed. Generated companion and aggregate consistency remains covered by the existing validators and canonical adopter builds.

Fingerprint format 2 retains exact sorted relation triples, their checksum, source/locator/citation/version/evidence-type claims, and per-record verified/retrieved dates. Relation capture includes the existing category equivalence, actor-role, constraint, grounding, and trigger predicates. Structural totals are retained. Intentional changes require a reviewed baseline diff in the owning adopter. The writer itself refuses date regression or removal; an evidence correction must explain and explicitly edit that baseline in a reviewed change. No automatic legal-value normalization or evidence-tier ranking is performed.

Diagnostics: `OF-SEMANTIC-DRIFT`, `OF-PROVENANCE-REGRESSION`, `OF-PROJECTION-STALE`, `OF-FRESHNESS-SOURCE`, `OF-FRESHNESS-BUILD`, and `OF-ENTITY-CONFLICT`. Declared Instrument correspondence compares lifecycle, operative status, enacted date, and effective date where both records assert a known value. Missing information and explicit `unknown` remain unknown, not agreement or a zero date. Correspondence is not owl:sameAs and is not inferred from titles.

Synthetic mutation tests run through the existing hardening gate. Every captured relation's same-host retargeting changes the fingerprint; every captured provenance claim is retained exactly. Backward or removed verification dates (including writer bypass), stale native source, orphaned projection artifacts, empty rebuilds, and conflicting declared lifecycle fail. Missing and unknown lifecycle values do not invent a disagreement. Restricted EveryAILaw data remains in its owning repository; shared fixtures use example.com.

An independent coverage guard discovers 63 IRI fields from schemas and the JSON-LD context, requiring 49 captured predicates or one of 14 explicitly justified exclusions. Removing a predicate from the implementation cannot remove its expected coverage. New unclassified schema/context relations also fail. The exclusions document the bounded top-level capture contract, not full nested semantic preservation.

Correspondence verification now reports resolved/compared pairs, compared fields, unknown fields, and unresolved external targets separately. Federation requires the owning private EveryAILaw fixture at `tests/fixtures/of-required-entity-pairs.json` (or an explicit `OF_REQUIRED_ENTITY_PAIRS` override). Required records, declarations, types, and known comparison fields must exist. Optional external references remain visible without automatically failing. This prevents a vacuous no-conflict result without treating unknown as equality or proof of legal applicability.

## Delivery dependency

Adopter build workflows and EveryAILaw federation currently select Obligation First's default branch. Fingerprint format 2 and its checker must therefore be delivered as a coordinated dependency change: stage explicit OF commit refs in adopter CI before advancing the checker, or accept a documented transition in which older baselines fail closed until all adopters publish format 2. A green OF-only suite does not establish that default-branch adopter CI accepts the new fingerprint contract. EveryAILaw federation must install adopter build dependencies before running the freshness checks. Record the accepted repository revisions after real delivery commits exist; disposable test snapshot commits are candidate evidence only.

The earlier September 1 tranche remains partly pending: adopter evidence-tier policies/raw digests, jurisdiction extension ownership, temporal causality, and consumer traversals belong in the P2 handoff. These changes do not expand the schema or alter released package manifests.
