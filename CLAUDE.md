# obligation-first — agent guidance

## Purpose

An open upper schema (methodology + JSON-LD context) for normative content —
laws, cases, and agreements — bound to the Semantic Arts [gist](https://semanticarts.com/gist/)
upper ontology. Models normative content by what it *requires* (obligations),
not what it *says* (text), so obligations become queryable across statutes,
proceedings, and joint interpretations. Canonical site: https://obligationfirst.org/.

It is the shared interstitial layer for the PAICE legal-graph portfolio:
EveryAILaw (statutory/regulatory Obligations), AI Incident Law (Proceedings/
Allegations/Determinations), and PubLedge (joint-interpretation Instruments/
Terms/Obligations). This repo owns the shared `@context`, JSON Schemas,
crosswalks, and validation harness — it does not centralize adopter data.

## Tech stack

- Node.js (>=20), plain ESM (`"type": "module"`), no framework/bundler.
- Validation via `ajv` + `ajv-formats` against hand-authored JSON Schemas.
- Content is JSON-LD (schema/context.jsonld) + Markdown spec docs.
- Static site in `docs/` (published to GitHub Pages) — `docs/index.html` is
  hand-edited; most of the rest of `docs/v1/` and `docs/releases/` is
  generated/mirrored — see AGENTS.md before touching anything under `docs/`.
- CI: GitHub Actions only (`.github/workflows/`), no other build system.

## Directory layout

- `PROTOCOL.md` — the spec itself (normative).
- `README.md`, `INTENT.md`, `ROADMAP.md`, `CHANGELOG.md`, `PRIOR-ART.md`,
  `ATTRIBUTION.md`, `CONTRIBUTING.md`, `SECURITY.md` — project docs.
- `schema/` — source-of-truth JSON Schemas + `context.jsonld` (edit here,
  not under `docs/v1/`).
- `examples/` — worked examples (air-canada, colorado-sb24-205,
  eu-ai-act-article-50, publedge-jia-utah-72, naming-profiles) with JSON
  records validated against `schema/`.
- `reference/` — crosswalks (gist/LegalRuleML/Akoma Ntoso/ELI-ECLI), adopter
  handoffs (`reference/handoffs/`), review notes, IRI/naming decisions.
- `scripts/` — all Node validation/build scripts (see below); `scripts/lib/`
  for shared helpers.
- `docs/` — the published static site (GitHub Pages), including
  `docs/v1/` (mirrored context/schemas) and `docs/releases/` (generated
  release packages). See `AGENTS.md` for exactly what's hand-edited vs
  generated here.
- `vendor/gist/` — pinned upstream gist ontology snapshot.
- `_workshop/` — informal design-conversation notes, not canonical.
- `MANIFEST.yaml` — content-hash ledger for release-pinned files.

## Conventions

- **This repo already has an `AGENTS.md` at its root with detailed,
  load-bearing build/release instructions — read it before editing anything
  under `docs/`, `schema/`, or cutting a release.** This CLAUDE.md
  summarizes; AGENTS.md is authoritative on mechanics.
- Version strings are single-sourced from `package.json` `version`, synced
  via `scripts/sync-version.mjs`. Never hand-edit version strings elsewhere.
- Release-pinned artifacts (PROTOCOL.md, schemas, CHANGELOG.md,
  package.json/lock, `docs/llms*`, `docs/agents.json`, `assistant-guide*`)
  are hash-checked via `MANIFEST.yaml`; changing them breaks
  `validate:contracts` until hashes are refreshed (`npm run hashes:update`)
  and, for a real release, a new `docs/releases/v<X.Y.Z>/` package is cut.
- `docs/releases/` directories are generated by `scripts/make-release.mjs`
  and refuse to overwrite an existing version dir — never hand-edit them.

## Build / validate (per docs — do not execute without asking)

```bash
npm install                          # or: npm ci
npm run validate                     # every example record vs its schema
npm run validate:graphs              # example-graph cross-record validation
npm run validate:contracts           # URL conventions, JSON-LD context coverage
npm run validate:hashes              # MANIFEST.yaml hash-drift check
npm test                             # full gate: all of the above + adopter-kit,
                                      # hardening regressions, anchor reports,
                                      # naming-profile, published-artifact checks
```

Release cutting is a multi-step procedure (version bump → sync-version →
CHANGELOG → release:package → hashes:update → `npm test`) — see AGENTS.md
"Release flow" for the exact sequence before ever running it.
