# Obligation-First — agent instructions

## Build pipeline

**`docs/index.html` is hand-edited.** No script writes it. Safe to edit directly. The repo's MANIFEST.yaml does not hash `docs/index.html`.

Generated and validated files:

- `docs/v1/context.jsonld` — copied from `schema/context.jsonld` by CI. Edit `schema/context.jsonld`, then CI mirrors.
- `docs/v1/schema/*.schema.json` — copied from `schema/*.schema.json` by CI. Edit `schema/*`, then CI mirrors.
- `docs/releases/v*/` — release-package manifests. Generated by `npm run release:package` (`scripts/make-release.mjs`); do NOT hand-edit. The generator derives the artifact list and URL patterns from the previous release's manifest and recomputes SHA-256 per artifact. It refuses to overwrite an existing release dir.
- Version strings across multiple files — `scripts/sync-version.mjs` is the single source of truth (reads `package.json` `version`). Run `node scripts/sync-version.mjs` after bumping the package version; `--check` mode verifies drift.
- Content hashes — tracked in `MANIFEST.yaml` for select files (NOT `docs/index.html`). `npm run validate:hashes` checks them; `npm run hashes:update` updates them after intentional content changes.

Validators that must pass before commit:

```bash
npm run validate              # validate-examples (every JSON record vs schema)
npm run validate:contracts    # URL conventions, JSON-LD context coverage, endpoint inventory
npm run validate:published    # docs/ mirror matches schema/ and examples/
npm run validate:hashes       # MANIFEST.yaml hash drift check
npm test                      # all of the above + adopter-kit + hardening + anchor reports
```

When editing `docs/index.html` (hand-edited but contract-validated): also run `npm run validate:contracts` to ensure URL conventions and endpoint inventory still match.

## Release flow

Any edit to a release-pinned artifact (PROTOCOL.md, schemas, CHANGELOG.md, package.json, package-lock.json, docs/llms*, docs/agents.json, assistant-guide*) breaks `validate:contracts` until the release package at the current `package.json` version carries fresh hashes. Cutting a release:

1. Bump the version: `npm version <X.Y.Z> --no-git-tag-version`.
2. Sync version strings: `node scripts/sync-version.mjs --date YYYY-MM-DD`.
3. Update CHANGELOG.md and any docs the release touches; sync `docs/v1/` mirrors of changed `schema/` files.
4. Write the release notes (a stub helps: run `npm run release:package` once, edit the generated `RELEASE_NOTES-v<X.Y.Z>.md`, then delete the dir and regenerate).
5. Generate the package: `npm run release:package -- --date YYYY-MM-DD --summary "<manifest summary>" --notes-from <path-to-final-notes>`. The script reads the version from package.json, derives artifacts and URLs from the previous release's manifest, recomputes all SHA-256 hashes, and fails if `docs/releases/v<X.Y.Z>/` already exists.
6. Update MANIFEST.yaml hashes: `npm run hashes:update`.
7. Run the full gate: `npm test`.

If a pinned artifact changes after the package was generated (including package.json itself), delete the release dir and rerun step 5 with the same `--date`/`--summary`/`--notes-from` so only the changed hashes move.
