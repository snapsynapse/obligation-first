# Obligation-First — agent instructions

## Build pipeline

**`docs/index.html` is hand-authored.** `sync-version.mjs` updates declared version, summary, and date spans; no script generates the whole page. Edit the surrounding content directly. The repo's MANIFEST.yaml does not hash `docs/index.html`.

Generated and validated files:

- `docs/v1/context.jsonld` — copied from `schema/context.jsonld` by CI. Edit `schema/context.jsonld`, then CI mirrors.
- `docs/v1/schema/*.schema.json` — copied from `schema/*.schema.json` by CI. Edit `schema/*`, then CI mirrors.
- `docs/releases/v*/` — release-package manifests. Generated by `npm run release:package` (`scripts/make-release.mjs`); do NOT hand-edit. The generator derives the exact artifact and URL inventory from `scripts/lib/contract-inventory.mjs`, carries compatibility metadata from the previous release, and recomputes SHA-256 per artifact. It refuses to overwrite an existing release dir.
- Version strings, current implementation-status source/mirror, scope summaries, and bundle/page dates are synchronized by `scripts/sync-version.mjs` from `package.json` and the explicit release date. Use `--check --date YYYY-MM-DD` to verify the intended date as well as managed content. Missing/duplicate markers and incompatible assistant-guide minor scope fail before writes. Release notes, feed summaries, and publication receipts remain separate author-owned inputs.
- Content hashes — tracked in `MANIFEST.yaml` for select files (NOT `docs/index.html`). `npm run validate:hashes` checks them; `npm run hashes:update` updates them after intentional content changes.

Validators that must pass before commit:

Literal
```bash
npm run validate              # validate-examples (every JSON record vs schema)
npm run validate:contracts    # URL conventions, JSON-LD context coverage, endpoint inventory
npm run validate:published    # docs/ mirror matches schema/ and examples/
npm run validate:hashes       # MANIFEST.yaml hash drift check
npm test                      # all of the above + adopter-kit + hardening + anchor reports
npm run validate:search       # also runs first in npm test and gates Pages
```

When editing `docs/index.html` (hand-edited but contract-validated): also run `npm run validate:contracts` to ensure URL conventions and endpoint inventory still match.

## Release flow

Any edit to a release-pinned artifact (PROTOCOL.md, schemas, CHANGELOG.md, package.json, package-lock.json, docs/llms*, docs/agents.json, assistant-guide*) breaks `validate:contracts` until the release package at the current `package.json` version carries fresh hashes. Cutting a release:

1. Bump the version: `npm version <X.Y.Z> --no-git-tag-version`.
2. Sync version, dates, implementation status and summaries: `node scripts/sync-version.mjs --date YYYY-MM-DD`.
3. Update CHANGELOG.md and any docs the release touches; sync `docs/v1/` mirrors of changed `schema/` files. Review the synchronized implementation state, write the release summary, and keep publication evidence distinct from local preparation.
4. Write the release notes (a stub helps: run `npm run release:package` once, edit the generated `RELEASE_NOTES-v<X.Y.Z>.md`, then delete the dir and regenerate).
5. Generate the package: `npm run release:package -- --date YYYY-MM-DD --summary "<manifest summary>" --notes-from <path-to-final-notes>`. The script reads the version from package.json, derives artifacts and URLs from the canonical inventory, recomputes all SHA-256 hashes, requires a real calendar date matching `MANIFEST.yaml` `bundle_date`, fixes canonical project identity, and fails if `docs/releases/v<X.Y.Z>/` already exists.
6. Update MANIFEST.yaml hashes: `npm run hashes:update`.
7. Run the full gate: `npm test` (including search, documentation parity/examples, frozen score replay, and release/hosted-verifier regressions).

After separately authorized publication, use the [hosted byte verifier](reference/hosted-artifact-verifier.md) with the exact tag and commit. Local tests do not establish hosted acceptance. Install commands disable audit uploads; dependency audit submission is a separate operation.

If a pinned artifact changes after the package was generated (including package.json itself), delete the release dir and rerun step 5 with the same `--date`/`--summary`/`--notes-from` so only the changed hashes move.

## Temporary handoffs and commit scope

Handoffs are temporary local queues, never historical documentation. Keep them ignored. Before removing a processed handoff, migrate any unique verified facts or accepted decisions into the owning reference, intent, or release-evidence record. Do not rename or copy a raw handoff into an archive.

`npm test` checks the candidate source for handoff files. Before any separately authorized commit, stage explicit reviewed paths (including intended handoff deletions), then run the staging-area check below. A deletion only in the working tree does not remove a handoff from the Git index.

Literal
```bash
npm run validate:publication-hygiene:staged
```

The staged check fails closed without this repository's Git index. Source archives are checked separately by the default publication-hygiene validator and do not need Git metadata.
